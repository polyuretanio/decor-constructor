# Decor Studio — публичный конструктор

Готовый статический сайт: HTML, CSS, JavaScript и только ассеты конструктора. Сервер приложений, ключи API, промпты и фотореференсы товаров не требуются.

Посетитель выбирает сцену, размещает украшения и скачивает JSON. Этот JSON нужно передать автору для фотореалистичной генерации. Кнопка «Сохранить композицию» также позволяет скачать плоский эскиз PNG; нейросеть на сайте не запускается.

## Локальный просмотр

В этой папке выполните:

```sh
python3 -m http.server 4174 --bind 127.0.0.1
```

Откройте http://localhost:4174. В браузере все вычисления и сохранение выполняются локально; проекты других посетителей друг другу недоступны.

## GitHub Pages

Загрузите содержимое этой папки в отдельный репозиторий. В Settings → Pages выберите Deploy from a branch, нужную ветку (обычно main) и /(root). Файл .nojekyll уже включён, отдельная сборка не нужна. Все пути относительные и поддерживают адрес вида /repository/.

Официальная инструкция: https://docs.github.com/en/pages/getting-started-with-github-pages/configuring-a-publishing-source-for-your-github-pages-site

## Обновление

Источник интерфейса и каталога — приватный проект decor-vis. После добавления украшений или сцен выполните из него:

```sh
npm run constructor:sync -- --out ../decor-constructor
```

Затем просмотрите изменения, сделайте commit и push только в репозитории публичного конструктора. Команда синхронизации сама ничего не публикует.

Не редактируйте сгенерированные файлы интерфейса и каталога вручную: обновление заменит их. .git, CNAME и прочие несгенерированные файлы сохраняются. Устаревшие файлы удаляются только по предыдущему constructor-bundle.json.

Сохраняйте ID существующих сцен и товаров. Изменившийся товар или несовместимо изменившаяся сцена должны получить новый ID, чтобы старые JSON оставались понятными. Каталог: 1 сцен, 12 украшений. Редакция: 6cdb644509ee89d2.
